# Data Requirements

This folder is included for transparency and provides the code used for data preprocessing in the context of our experiments.

While the data shared in this repository is the data used in practice for the experiments detailed in the associated research article (see [TwinViews](#twinviews)), the overall framework remains general and the data structure expected to run the rest of the pipeline is described in the [following section](#data-format).

## Data Format

This codebase relies primarily on datasets with three key features: texts, binary labels, and domains (or conditions).

> [!IMPORTANT]
> All information regarding the names of the fields must be filled out in the [data configuration file](../configs/data_config.json).

The dataset must be stored as a `.csv` dataframe at the path provided by the [data configuration file](../configs/data_config.json): `data_config.json` -> `<dataset_name>` -> `"dataframe_path"`; where the `<dataset_name>` must be consistent with the one provided in the [experimental configuration file](../configs/exp_config.json) (`exp_config.json` -> `"dataset_name"`).

This dataframe must contain the following features, which must be documented in the [data configuration file](../configs/data_config.json):

- Texts: a column with the textual inputs used to extract the hidden states representations in LLMs.
    - `data_config.json` -> `<dataset_name>` -> `"text_col"`
- Labels: the (binary) labels encoding the contrasts of the studied concept (in our test case: left- / right- political views)
    - `data_config.json` -> `<dataset_name>` -> `"label_col"`
- Domains: the conditions differing between examples (in our case the different policy issues, e.g.; tax, education, gun control, healthcare, climate change, ...)
    - `data_config.json` -> `<dataset_name>` -> `"domain_col"`

The dataframe should also include general purpose information, such as:
- Sample identifiers: unique identifiers for each of the samples
    - `data_config.json` -> `<dataset_name>` -> `"id_col"`
- [Opt.] Group identifiers: optionally, if data was generated by groups (in our case parallel left- / right- leaning stances), provide an identifier for those (non-independent) groups
    - `data_config.json` -> `<dataset_name>` -> `"pairwiseid_col"`

Additionally, the [data configuration file](../configs/data_config.json) must provide:
- Unique labels: the list of unique labels (in our case: `['l', 'r']`)
    - `data_config.json` -> `<dataset_name>` -> `"labels"`
- Hidden States storing path: the base folder to store the latent representations extracted from the models when running [`scripts/get_activations.py`](../scripts/get_activations.py). The activations will be stored into folders named after the models used within this base repository.
    - `data_config.json` -> `<dataset_name>` -> `"hs_path"`

## `TwinViews` preprocessing

For transparency, the code used to preprocess [TwinViews](https://huggingface.co/datasets/wwbrannon/twinviews-13k) is provided in the [preprocessing folder](./preprocessing) in the form of `.ipynb` jupyter notebooks. 

> [!TIP]
> The resulting dataset used in practice for the experiments presented in the paper is directly provided in the [preprocessed folder](./preprocessed), stored in `.csv` as [twinviews_prepro.csv](./preprocessed/twinviews_prepro.csv).

The first notebook ([topics_to_issues_twinviews.ipynb](./preprocessing/topics_to_issues_twinviews.ipynb)) primarily retrieves topics based on  aggregated pairs of left-/right- stances. An additional preprocessing layer makes sure that none of the original topics (from the TwinViews dataset) are splitted into different bertopics (retrieved automatically).
These topics are then *manually* named.
Then, the second notebook ([filter_twinviews.ipynb](./preprocessing/filter_twinviews.ipynb)) applies these new 'issue' labels to the dataset, filters data to retain only the ten most common political issues and stores the resulting dataset into [`twinviews_prepro.csv`](./preprocessed/twinviews_prepro.csv).
